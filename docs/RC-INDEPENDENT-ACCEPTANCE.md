# 2.0 独立终端验收记录模板

本模板用于实际准备分发的候选包。源码测试、本机文件夹版测试和安装包实测分别记录，不能互相替代。当前状态默认全部为“未测试”，填写证据后才改为通过。

## 固定验收对象

- RC 版本、Git 提交、构建任务 URL：
- 安装包原始文件名、字节数、SHA256：
- ZIP 原始文件名、字节数、SHA256：
- 实际安装 EXE 的签名状态、签名主体、时间戳验证结果：
- 测试者、测试日期、匿名设备编号：
- Windows 版本/构建、x64、普通账户或管理员账户：
- 屏幕分辨率、缩放比例、单屏/双屏：
- Node/Python 是否未安装；VC++ 运行库是否已安装：
- Office 产品、版本和激活情况；无 Office 的设备另填一份：
- 杀毒产品与病毒库版本、扫描时间、检测名、厂商复核单号：
- 测试课件与项目副本名称、初始内容清单/哈希：

## 签署发布结论

- 阻断项：启动失败、项目打不开、已保存数据丢失、页码错配、并发覆盖错误、核心内容不能显示，必须关闭并在最终候选包复测。
- 一般排版瑕疵可作为已知限制，但必须写明影响范围、触发条件与临时办法。
- 旧版报毒不能直接标为误报。保留检测名、包哈希和厂商复核结果，不关闭防护、不添加排除项。
- 独立验收、安装升级与签名/杀毒复核未完成前，保持 prerelease 标记；自动测试全绿不构成替代证据。
- 若验收后又构建了新包，新 SHA256 必须建立新记录，至少重测安装、启动、打开项目、保存重开与本次改动涉及的用例；签名后也重新核验最终分发文件。
- RC.1 改成 2.0.0 会改变元数据和包哈希，不能仅凭代码相同跳过正式包检查。
