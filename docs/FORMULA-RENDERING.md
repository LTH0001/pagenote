# 公式显示反斜杠源码

已经复现的一种情况是：从聊天窗口或经过转义的文本中复制公式，原本的 `\(...\)` 或 `\[...\]` 变为 `\\(...\\)` 或 `\\[...\\]`。旧版只处理单层转义，会留下反斜杠或交给 Markdown 当作普通文字，导致公式不显示或出现解析错误。这是输入格式兼容问题，不能仅归因于电脑配置。

beta.5 开发版会在渲染时识别这两种分隔符。分隔符和公式命令都被双重转义时，会修复可明确识别的成套转义。正常公式中的矩阵换行、行内代码与代码围栏保持原样，不对整篇笔记做全局反斜杠替换，也不改写导入的原始 Markdown。

支持的形式包括 `$...$`、`$$...$$`、`\(...\)`、`\[...\]`，以及 `math`、`latex`、`tex` 代码围栏。复制导致的双重转义也有对应测试。仅在代码围栏中作为示例展示的公式分隔符不会自动变成公式。

同一组用例在修复前的程序中出现 KaTeX 解析错误；修复后的源码与 Windows 文件夹构建均验证公式数量、矩阵结构、无残留分隔符、离线本地字体以及编辑保存后的显示。

这不代表任意损坏的 LaTeX 都可以自动修复。若仍有异常，请提供出现问题的最小原文和截图，以区分分隔符转义、LaTeX 语法、代码围栏和字体资源问题。

跨行的 `$$...$$` 公式也可以让分隔符紧邻首尾内容。渲染前会把这种块公式的分隔符放到独立行，保留公式中的矩阵换行，不修改原始笔记。例如：

````text
$$\frac{a}{b}
\le c.$$
````

若旧版遇到这种格式显示源码，可以先手动让起止 `$$` 各自独占一行。
